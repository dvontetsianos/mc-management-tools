================================================================
MC MANAGEMENT TOOLS - SERVER SETUP GUIDE
================================================================
For moving the app to a NEW Windows PC, with the data of the
current server. Do the parts in order. Each command box is one
paste: paste it, press Enter, wait for it to finish.

Use EXACTLY these two folders (update.bat expects them):
    C:\MC Management Tools      the app
    C:\nssm-2.24                the service tool

"Admin PowerShell" = Start menu -> type PowerShell -> right-click
-> "Run as administrator".

PORT: the app uses port 8000. If another program on the new PC
already uses 8000, use 8080 everywhere this guide says 8000
(service, firewall, test address) and make a new QR code.


----------------------------------------------------------------
PART 0 - WRITE DOWN FROM THE CURRENT SERVER
----------------------------------------------------------------

On the CURRENT server, open PowerShell and note the versions:

    python --version

    node --version

Copy the file C:\MC Management Tools\.env to a USB stick.
It holds SECRET_KEY (keeps everyone logged in after the move)
and BACKUP_DIR (where backups go). Never send it to anyone,
never put it in git.

Open Task Scheduler and note the backup task(s): the name, the
times (03:00 and 12:00) and the "When running the task, use the
following user account" setting. You'll disable them on the
switch day.


----------------------------------------------------------------
PART 1 - INSTALL THE SOFTWARE (new PC)
----------------------------------------------------------------

In an Admin PowerShell, one at a time. Use the same Python
version as the current server (change 3.14 if Part 0 showed
another one, e.g. 3.13):

    winget install -e --id Git.Git --scope machine

    winget install -e --id Python.Python.3.14 --scope machine

    winget install -e --id OpenJS.NodeJS.LTS --scope machine

    winget install -e --id Microsoft.VisualStudioCode --scope machine

Close PowerShell and open it again, then check:

    python --version

    node --version

    git --version

All three must print a version. If "python" opens the Microsoft
Store instead: Settings -> Apps -> Advanced app settings -> App
execution aliases -> switch OFF both "python" entries, then open
PowerShell again.


----------------------------------------------------------------
PART 2 - GET THE APP
----------------------------------------------------------------

In PowerShell (normal is fine):

    cd C:\

    git clone https://github.com/dvontetsianos/mc-management-tools.git "MC Management Tools"

    cd "C:\MC Management Tools"

This gives the "main" branch, the one servers run.


----------------------------------------------------------------
PART 3 - BACKEND
----------------------------------------------------------------

Still in C:\MC Management Tools:

    python -m venv .venv

Allow PowerShell to run the activate script (once per user,
answer Y if asked):

    Set-ExecutionPolicy -Scope CurrentUser RemoteSigned

    .venv\Scripts\activate

You should now see (.venv) at the start of the line.

    pip install -r requirements.txt

Put the .env from the USB stick in C:\MC Management Tools
(next to requirements.txt). Open it and check BACKUP_DIR: that
folder must exist on THIS PC. If it doesn't, create it (or
change BACKUP_DIR to a folder that does).

Create the two runtime folders:

    mkdir uploads

    mkdir logs


----------------------------------------------------------------
PART 4 - FRONTEND
----------------------------------------------------------------

Do NOT create frontend\.env.local. Without it the app talks to
whatever address it was opened from, so the IP can change any
time.

    cd frontend

    npm install

    npm run build

    cd ..

This creates frontend\dist, which the backend serves. (Later,
update.bat does this for you. The first time it's by hand,
because update.bat also restarts the service, which doesn't
exist yet.)


----------------------------------------------------------------
PART 5 - TEST DATA
----------------------------------------------------------------

For testing, use a COPY of the current server's data (the real
copy happens on the switch day, Part 11):

  1. From the current server's backup folder, take the newest
     zip from database\daily. Unzip it: inside is assets.db.
     Put it in C:\MC Management Tools (next to requirements.txt).
  2. Copy the current server's C:\MC Management Tools\uploads
     folder over the empty uploads folder here.

No create_admin.py and no migrate scripts: this database
already has the users and every update.


----------------------------------------------------------------
PART 6 - TEST RUN
----------------------------------------------------------------

In C:\MC Management Tools with (.venv) showing:

    uvicorn app.main:app --host 0.0.0.0 --port 8000

On this PC open http://localhost:8000 and check:
  - the login page loads, you can log in
  - items show with their photos
  - pressing F5 on an inner page (e.g. F&B Items) still works

Press Ctrl+C in PowerShell to stop it.


----------------------------------------------------------------
PART 7 - INSTALL AS A WINDOWS SERVICE (NSSM)
----------------------------------------------------------------

Download NSSM 2.24 from https://nssm.cc/download and unzip it so
that this file exists:  C:\nssm-2.24\win64\nssm.exe

In an Admin PowerShell, ONE line at a time:

    & "C:\nssm-2.24\win64\nssm.exe" install MCManagementTools "C:\MC Management Tools\.venv\Scripts\uvicorn.exe" "app.main:app --host 0.0.0.0 --port 8000"

    & "C:\nssm-2.24\win64\nssm.exe" set MCManagementTools AppDirectory "C:\MC Management Tools"

    & "C:\nssm-2.24\win64\nssm.exe" set MCManagementTools AppStdout "C:\MC Management Tools\logs\service-out.log"

    & "C:\nssm-2.24\win64\nssm.exe" set MCManagementTools AppStderr "C:\MC Management Tools\logs\service-err.log"

    & "C:\nssm-2.24\win64\nssm.exe" set MCManagementTools AppExit Default Restart

    & "C:\nssm-2.24\win64\nssm.exe" start MCManagementTools

    & "C:\nssm-2.24\win64\nssm.exe" status MCManagementTools

The last one must print SERVICE_RUNNING. The service starts by
itself when Windows starts, even with nobody logged in.


----------------------------------------------------------------
PART 8 - FIREWALL
----------------------------------------------------------------

In an Admin PowerShell:

    netsh advfirewall firewall add rule name="MC Management Tools" dir=in action=allow protocol=TCP localport=8000

From a phone on the same Wi-Fi open http://<this PC's IP>:8000
(find the IP with "ipconfig", the IPv4 Address line).


----------------------------------------------------------------
PART 9 - AUTOMATIC BACKUPS (03:00 and 12:00)
----------------------------------------------------------------

In an Admin PowerShell, ONE box at a time:

    $action = New-ScheduledTaskAction -Execute "C:\MC Management Tools\.venv\Scripts\python.exe" -Argument "backup_db.py" -WorkingDirectory "C:\MC Management Tools"

    $triggers = @((New-ScheduledTaskTrigger -Daily -At 03:00), (New-ScheduledTaskTrigger -Daily -At 12:00))

    $settings = New-ScheduledTaskSettingsSet -StartWhenAvailable -ExecutionTimeLimit (New-TimeSpan -Hours 1)

    Register-ScheduledTask -TaskName "MC Management Tools Backup" -Action $action -Trigger $triggers -Settings $settings -User "SYSTEM" -RunLevel Highest

StartWhenAvailable = if the PC was off at 03:00, the backup runs
as soon as it's back on.

Test it now:

    Start-ScheduledTask -TaskName "MC Management Tools Backup"

Wait a minute, then check:
  - BACKUP_DIR\database\daily has a new mc_backup_....zip
  - BACKUP_DIR\READ ME - backup status.txt says it went fine
  - if not: C:\MC Management Tools\logs\backup_log.txt says why

Note: the task runs as SYSTEM. If .env has BACKUP_SHARE_DIR
(a network folder), SYSTEM may not be allowed to write there -
the status file will say so. Local BACKUP_DIR always works.


----------------------------------------------------------------
PART 10 - FINAL CHECK
----------------------------------------------------------------

  1. Restart the PC. Don't log in.
  2. From a phone, open http://<this PC's IP>:8000. It must load.
     That proves the app runs on its own.


----------------------------------------------------------------
PART 11 - THE SWITCH DAY (15-30 minutes, nobody counting)
----------------------------------------------------------------

On the CURRENT server (Admin PowerShell):

  1. Open the app -> System Monitor -> Back up now.

  2. Stop the app:

    & "C:\nssm-2.24\win64\nssm.exe" stop MCManagementTools

  3. Copy C:\MC Management Tools\assets.db and the uploads
     folder to the USB stick (or over the network).

On the NEW PC (Admin PowerShell):

  4. Stop the app:

    & "C:\nssm-2.24\win64\nssm.exe" stop MCManagementTools

  5. Replace C:\MC Management Tools\assets.db and the uploads
     folder with the ones from step 3.

  6. Start the app:

    & "C:\nssm-2.24\win64\nssm.exe" start MCManagementTools

  7. Check: log in, items, photos, a Quick Count from a phone,
     the open counts are still there.

Back on the CURRENT server, so it never runs again by mistake:

  8. Disable the service:

    & "C:\nssm-2.24\win64\nssm.exe" set MCManagementTools Start SERVICE_DISABLED

  9. Task Scheduler -> right-click its backup task(s) ->
     Disable. (Two PCs must never back up into the same folder.)

Keep the old PC untouched for a week or two, as a fallback.


----------------------------------------------------------------
FROM NOW ON - UPDATES
----------------------------------------------------------------

If an update comes with a database script, run it right after
update.bat. In PowerShell, in C:\MC Management Tools, type
python and the script's real name, for example:

    python migrate_user_names.py


----------------------------------------------------------------
GOTCHAS
----------------------------------------------------------------

- Service and firewall commands need an Admin PowerShell, or
  they fail with "Access is denied".
- A quoted .exe path in PowerShell needs & in front:
      & "C:\nssm-2.24\win64\nssm.exe" status MCManagementTools
- Paste ONE command at a time. Many lines at once can run out
  of order.
- If "git pull" says "your local changes would be overwritten",
  a file was edited on the server. Undo that edit with
      git checkout -- <file>
  and run update.bat again. Never edit code on the server.
